# Ostium 0.2.9 Clash 订阅 DNS 修复

> 现象：Clash Verge 导入订阅后提示“订阅本身会修改 DNS，已自动关闭 DNS 覆写”，
> 随后所有域名的解析都超时，四条线路看起来全部不可用。

## 日志

```text
dns resolve failed: all DNS requests failed, first error:
requesting https://1.1.1.1:443/dns-query: context deadline exceeded
```

## 根因

生成的 Clash 配置包含：

```yaml
dns:
  nameserver:
    - https://1.1.1.1/dns-query
    - https://8.8.8.8/dns-query
  proxy-server-nameserver:
    - https://1.1.1.1/dns-query
```

Clash Verge Rev 检测到订阅自带 DNS 后，会关闭客户端的“DNS 覆写”以避免冲突。
但 `1.1.1.1:443` 在部分网络不可达，于是：

1. 代理服务器域名 `vpn.ostium.cn` 无法解析；
2. 所有目标域名也无法解析；
3. 四条线路全部表现为不可用。

这不是节点端口或证书问题。服务端已确认：

```text
443/TCP   sing-box
443/UDP   sing-box (Hysteria2)
9443/TCP  sing-box (Trojan)
8388/TCP  sing-box (Shadowsocks)
```

## 修复

- Clash / Mihomo 订阅不再写入 `dns` 段，客户端保留自己的 DNS 覆写和解析配置。
- 订阅不再写入 `mixed-port`、`allow-lan`、`bind-address`、`mode`、`log-level`、
  `ipv6`，这些属于客户端设置，订阅不应覆盖。
- 去掉 `GEOIP,CN,DIRECT` 规则，改用不需要外部数据库的
  `DOMAIN-SUFFIX,cn,DIRECT`。缺少 MMDB 的客户端不会因此拒绝启动。
- sing-box 订阅不再强制 DoH，也不再设置 `default_domain_resolver`。
- 订阅中不再出现 `1.1.1.1`。
- 回归测试同时覆盖渲染器和 HTTP 订阅端点。

## 其他客户端的等价性

- `v2rayN` / Xray：使用 Base64 或纯 URI，不读取订阅 DNS；VLESS/Trojan/SS2022
  协议参数已用 Xray 实测。
- Shadowrocket / NekoBox：使用标准 URI，DNS 由客户端管理。
- sing-box GUI：使用 sing-box JSON，已实测四条线路。
- Hysteria2 需要客户端支持 UDP/QUIC；SS2022 需要较新的客户端。旧客户端可改用
  VLESS Reality 或 Trojan 线路。
- 如果客户端自身的 DNS 被设置为不可达的服务器，任何订阅都无法解析域名；
  此时应改用系统 DNS 或可达的国内 DNS。
- 线上服务器已升级到 0.2.9：`/healthz` 和 `/readyz` 均为 200，sing-box
  监听 443/TCP、443/UDP、9443/TCP、8388/TCP。

## 客户端操作

1. 在 Ostium 重新复制 Clash 订阅链接；
2. 在 Clash Verge 中更新订阅（或删除旧配置后重新导入）；
3. 重启 Clash 内核；
4. 如果之前“DNS 覆写”被自动关闭，重新开启或恢复默认 DNS 设置。

新订阅不会修改客户端 DNS，因此不会再触发该提示。清理旧配置后重新导入，
确保客户端没有继续使用缓存里的旧 DNS 段。
