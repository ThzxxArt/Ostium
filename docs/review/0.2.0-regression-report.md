## 4. 真实 E2E 证据

```text
PROXY_BODY=<!doctype html><html lang=en><head>...
E2E_USED=2016
QUOTA_STATE=False quota_exceeded 1008
QUOTA_SUB=403
E2E_OK
```

- 临时数据目录，Trojan `0.0.0.0:8443`，自签证书 `localhost`。
- 客户端使用订阅生成的 `tls.certificate_public_key_sha256`，真实访问 `http://example.com`。
- 10 字节配额用户真实产生 1008 字节后被禁用，订阅返回 403。
- 详细记录：[`docs/operations/e2e-evidence.md`](../operations/e2e-evidence.md)。

## 5. 阻塞项与残余风险

| 项 | 原因 | 影响 |
|---|---|---|
| 443 绑定 | 当前用户无 root/CAP_NET_BIND_SERVICE | 本地用 8443；生产 unit 已配置 capability |
| systemd 实机 | 无 root、无 `/opt/ostium` 安装 | unit 静态审查 + shellcheck；未实机启动 |
| Docker build/up | 本机无 Docker | CI package 已通过 `docker compose config`；e2e workflow 的 build/up 本轮未触发 |
| Caddy/certbot | 未安装、需 root | 配置/hook 静态审查 |
| PostgreSQL | 本机无服务 | CI postgres 矩阵 |
| GitHub CI | 尚未推送本轮提交 | 推送后等待 ci/ui |

残余风险：Caddy/certbot 的真实 TLS 续期、systemd 的 443 capability、Docker 多容器网络
只能在目标主机验证；本轮没有伪造这些结果。
