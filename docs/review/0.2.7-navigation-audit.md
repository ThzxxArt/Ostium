# Ostium 0.2.7 控制台导航审计

> 审计对象：0.2.7
> 目标：正常管理操作不再跳转到 Django Admin；控制台内没有“另一个网站”的入口。

## 1. 审计方法

对所有控制台模板执行：

```bash
grep -RIn "{% url 'admin:" src/ostium/templates/console \
  src/ostium/templates/partials src/ostium/templates/registration
```

再逐页用 Playwright 登录访问 14 条控制台路由，断言：

- 页面中不存在 `href="/admin/`；
- 页面正文不包含 `Django Admin`；
- 1440 / 390 均无横向滚动。

## 2. 修复前：8 个模板、14 个跳站链接

| 页面 | 跳站入口 |
|---|---|
| 总览 | 新增用户（页头、快捷操作） |
| 用户 | 高级管理、新增用户、行内编辑 |
| 用户详情 | Admin 编辑 |
| 订阅 | 新增用户 |
| 线路 | 高级编辑 |
| 证书 | Admin 列表、详情 |
| 审计 | Admin 视图 |
| 侧栏 / 用户菜单 / 命令面板 | Django Admin、新增用户 |

## 3. 修复后

| 原入口 | 现在 |
|---|---|
| 用户 → 高级管理 | 删除；控制台用户页本身即完整管理界面 |
| 用户 → 新增用户 | 新增控制台页面 `/users/new/` |
| 用户行内编辑 | 指向控制台用户详情 `/users/<uuid>/` |
| 用户详情 → Admin 编辑 | 删除；账号设置表单就在页面内 |
| 总览 / 订阅 → 新增用户 | 指向 `/users/new/` |
| 线路 → 高级编辑 | 改为“证书管理”，指向 `/certificates/` |
| 证书 → Admin 列表 / 详情 | 删除；证书卡片已展示全部信息 |
| 审计 → Admin 视图 | 删除；筛选和分页都在控制台 |
| 侧栏 / 用户菜单 | 删除 Django Admin 入口 |
| 命令面板 → 新增用户 | 指向 `/users/new/` |

Django Admin 仍可通过 `/admin/` 直接访问，作为**应急数据管理**界面保留；
它不再出现在任何正常导航中，页头显示“常规操作请返回 Aurora 控制台”。

## 4. 新增用户页

`/users/new/` 使用 Aurora 布局，字段：

- 用户名
- 流量配额（`100G`、`1.5T`，留空不限）
- 配额周期（总量 / 每月重置）
- 到期时间（留空永不过期）
- 备注
- 创建后立即启用

创建成功后跳转到用户详情，凭据和订阅 token 自动生成。
