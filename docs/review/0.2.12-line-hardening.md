# Ostium 0.2.12 线路稳定性与防封禁

> 目标：让线路异常在服务器侧可见，并提供可控的端口/伪装轮换操作。

## 1. 线路健康

新增 `src/ostium/proxy/health.py`：

- 通过 `psutil.net_connections` 检查启用线路的 TCP/UDP 监听；
- 复用 `Inbound.validation_errors()` 检查证书、密钥和端口；
- Hysteria2 未启用 salamander 时标记「注意」；
- 控制台新增 `/inbounds/health/` 页面；
- worker 在维护循环中检查，端口异常产生 `inbound_unhealthy` 告警。

CLI：

```bash
ostium inbound check
ostium inbound check --json
```

## 2. 防封禁操作

### 随机端口

- 控制台每张线路卡片新增「随机端口」；
- 候选范围 20000–59999；
- 排除本机监听端口和其他 Ostium 同传输线路的端口；
- CLI：`ostium inbound randomize-port <kind>`。

### Reality 伪装轮换

- 控制台「更换伪装」；
- 从常见 TLS 目标中选择 443 可达且不同于当前值的域名；
- 更新 `server_name` / `handshake_server` / `handshake_port`；
- CLI：`ostium inbound rotate-camouflage`；
- 需要客户端重新导入订阅。

### Hysteria2 混淆

现有 `rotate-keys` 对 Hysteria2 实际轮换的是 salamander 混淆密码；控制台按钮
改名为「轮换混淆」，并在健康页提示未启用混淆的情况。

## 3. 稳定性

- 健康检查在 sing-box 启动后 15 秒内跳过，避免启动竞态误报；
- 端口恢复后 `inbound_unhealthy` 自动 resolve；
- 随机端口操作会检查本机监听和 Ostium 内部冲突；
- 移动端按钮自动换行，不再横向溢出。
