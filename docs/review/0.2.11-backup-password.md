# Ostium 0.2.11 页面备份密码

> 目标：让自动备份密码可以在控制台设置，同时不破坏“备份不能包含自己的密码”
> 这一安全边界。

## 之前的问题

- 设置页只有「启用自动备份」开关，没有密码输入；
- 自动备份只读取 `OSTIUM_BACKUP_PASSWORD` 环境变量；
- 开启开关但没设置密码时，worker 只产生 `backup_failed` 告警，不创建备份；
- 手动备份表单的标签是英文。

## 现在的行为

### 页面设置

「设置 → 自动备份密码」：

- 输入密码 + 确认密码；
- 写入 `/var/lib/ostium/secrets/backup-password`；
- 目录 0700，文件 0600；
- 不进入数据库，不进入备份归档；
- 可以清除页面密码（环境变量管理的密码不能被页面清除）。

### 密码优先级

```text
OSTIUM_BACKUP_PASSWORD 环境变量
  > secrets/backup-password 页面文件
```

页面会显示当前来源：

- `env`：环境变量管理；
- `file`：页面密码文件；
- 空：未设置。

### 使用方

- worker 自动备份；
- `ostium backup create`；
- `ostium backup restore`；
- 备份 API。

都优先使用环境变量，缺失时回退到页面密码文件。

### 手动备份表单

「系统 → 创建备份」的标签和帮助文本已改为中文，仍然要求每次输入密码，适合
临时备份或恢复前快照。

## 验证

```text
401 passed, 3 skipped
coverage 90.24%
UI 8 passed
```

测试覆盖：

- 页面保存密码、两次输入不一致；
- 文件权限 0600；
- 环境变量优先级；
- worker 从文件读取密码并创建自动备份；
- Dashboard 备份检查项使用文件密码；
- 清除页面密码。

## 安全说明

页面密码文件与 `ostium.env` 一样位于服务器上，因此不能防御“服务器被完全攻破”。
它防的是：

- 备份文件单独泄露；
- 误把备份复制到对象存储/另一台机器后，密码随备份一起泄露；
- 数据库泄露后直接得到备份密码。

真正的灾备仍要求把 `.ostb` 和密码分别保存到不同位置。
