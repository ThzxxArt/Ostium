## 1. 0.1.x 的处置：全部删除

### 1.1 处理原则

- **main 分支不保留任何 0.1.x 代码、文档、配置、脚本、测试、部署文件。**
- 0.1.x 只存在于 git 历史与 `v0.1.12` tag 中，不作为兼容、迁移、参考目标。
- 不读取旧数据库、不导入旧用户、不保留旧订阅 token、不兼容旧 API。
- 不写“升级指南”“迁移工具”“兼容层”“deprecated 警告”。
- `CHANGELOG.md` 从 0.2.0 重新开始；旧变更记录留在 git tag。
- 旧版本用户如果要用 0.2.0：**全新安装、重新创建用户、重新发订阅**。这是明确的产品决策。

### 1.2 仓库重建方式

建议从 `main` 开一个 orphan 分支 `rewrite/0.2.0-server`：

```bash
git switch --orphan rewrite/0.2.0-server
# 只保留 LICENSE、NOTICE、品牌 logo、.gitignore
# 其余全部删除，再从零搭建
```

这样做的好处：

- 不带着 0.1.x 的目录结构和历史包袱做“边删边写”。
- review 时看到的是一个全新的服务端项目。
- 发布时把 orphan 分支合并回 `main`，main 树里没有旧文件；git 历史仍可追溯。

> 如果爸爸要求连 git 历史也重写，那是破坏性操作，需要单独确认；默认不重写历史。

## 2. 目标架构

### 2.1 进程模型

```text
systemd / Docker Compose
├─ ostium-web.service      Gunicorn + Django（127.0.0.1:8000）
├─ ostium-worker.service   数据面 worker（无 HTTP；监督 sing-box）
│   └─ sing-box            443/tcp + 443/udp
├─ ostium-jobs.service     django-q2 qcluster（备份/证书/导出）
├─ caddy.service（可选）    TLS + 反代 8443 -> 127.0.0.1:8000
└─ certbot.timer（外部）    证书签发/续期 -> deploy hook -> ostium cert sync
```

### 2.2 为什么不再有 `ostium-core`

0.1.x 的 core 服务是为了客户端 TUN 的 root 隔离。0.2.0 没有 TUN，服务端只需要绑定 443：

- worker 以 `ostium` 用户 + `CAP_NET_BIND_SERVICE` 运行。
- sing-box 是 worker 的子进程，继承 capability。
- DB 是唯一事实源；worker 每次从 DB 生成配置。
- 不再需要：`core.token`、core API、`last-good` 协议、`enforcement.json`、core watchdog、reconcile。
- 代价：worker 重启/升级时隧道中断 1–3 秒；文档明确，换取少一整层自研协议。

### 2.3 信任边界

| 边界 | 可信 | 不可信 | 控制 |
|---|---|---|---|
| 互联网 -> 443 | 已认证代理用户 | 扫描/未认证流量 | sing-box 认证 |
| 互联网 -> 管理面 | 管理员（TLS+TOTP） | 公网攻击者 | 默认回环；Caddy TLS；django-otp |
| 浏览器 -> Django | 管理员会话 | 恶意网页/DNS rebinding | CSRF、ALLOWED_HOSTS、CSP |
| web -> worker | 同一 `ostium` 用户 | 无独立边界 | 服务端无 root/TUN；worker 只执行固定 sing-box |
| worker -> sing-box | 固定二进制、生成配置 | 任意命令/路径 | `sing-box check` + 固定 argv |
| 供应链 | 固定版本+SHA256+SBOM | 镜像/二进制篡改 | 发布校验 |

> 0.1.x 的 web/core 隔离是客户端 TUN 的产物；0.2.0 删除客户端后不再需要。若未来要更强隔离，可把 worker 拆成独立用户 + Unix socket，但不是 0.2.0 范围。

### 2.4 数据流

```text
Admin/API -> DB（用户/线路/证书/设置）
                 |
                 v
          RuntimeState.desired_revision++
                 |
                 v
 worker（每秒检查）-> 生成配置 -> sing-box check
                 |
       成功 -> 原子替换 + 重启 sing-box
       失败 -> 保留上一版 + 告警
                 |
                 v
 V2Ray gRPC 统计 -> 配额/到期 -> 更新 DB -> mark revision
                 |
                 v
 客户端 -> /sub/<token> -> 标准订阅 -> sing-box 客户端 -> 443 -> 出口
```

## 4. 现代 UI 设计：Aurora Server Console

### 4.1 设计目标

- **第一眼**：像 2026 年的精品云控制台，不是 Django Admin 默认皮肤。
- **第一分钟**：知道服务是否正常、谁在线、流量多少、哪里有问题、下一步点哪里。
- **日常**：用户/订阅/线路/证书操作不超过 3 次点击。
- **移动**：手机也能完成用户管理和订阅复制。
- **可访问**：WCAG 2.2 AA、键盘、读屏、减少动效、200% 缩放。

### 4.2 视觉语言

**关键词**：深空、极光、玻璃、克制、数据感、呼吸感。

**用色规则**：

- 80% 中性表面，15% 文本/结构，5% 强调色。
- 状态同时用图标 + 文案，不只靠颜色。
- 正文对比度 ≥ 4.5:1；弱文本 ≥ 3:1。
- 玻璃质感只用于侧栏、顶栏、Hero、浮层；表格/表单用实色，保证可读性。
- 背景用静态极光径向渐变 + 2% 噪点；不做持续动画；`prefers-reduced-transparency` 回退纯色。

### 4.6 页面设计

#### 登录

- 55/45 分屏：左侧极光品牌视觉 + 产品名 + 一句定位；右侧登录卡。
- 用户名/密码 → 如需 TOTP，第二步显示 6 位验证码 + 恢复码入口。
- 错误就地显示；锁定/限速文案明确；不暴露用户是否存在。
- 首次登录强制改密；公网管理面强制 TOTP。

#### Dashboard

- **Server Pulse Hero**：
  - 大状态环（运行/停止/降级）；
  - 运行时长；
  - 当前上行/下行速率；
  - 今日流量；
  - 在线用户数；
  - 最近一次配置应用时间/hash。
- 4 张 KPI 卡：用户总数/在线、今日流量、核心状态、证书最近到期。
- 24h/7d 流量面积图（上行/下行双色）。
- 在线用户 Top 5 表格（用户名、速率、配额、最后在线）。
- 健康堆叠卡：DB、worker、sing-box、磁盘、DoH、证书。
- 最近告警/任务时间线。
- 快捷操作：新增用户、复制订阅、导入证书、重启核心、创建备份。

#### 用户列表

- 搜索、状态筛选（全部/启用/禁用/到期/超配额/在线）、排序。
- 表格列：头像首字母、用户名、状态胶囊、配额环、已用/配额、到期、最后在线、协议徽标、操作。

## 6. 数据面设计

### 6.1 配置生成

`engine/config.py` 纯函数：

- 输入：Inbound 列表、启用的 ProxyUser、证书路径、DNS 设置、日志级别。
- 输出：sing-box server config dict。
- Pydantic 模型校验后 `model_dump(mode="json", exclude_none=True)`。
- 规范化 JSON 计算 SHA256；写文件时缩进 2。
- 配置 0600；日志/诊断永不输出完整配置。

顶层结构：

```json
{
  "log": {"level": "info", "timestamp": true},
  "dns": {"servers": [...], "strategy": "ipv4_only", "final": "local"},
  "inbounds": [...],
  "outbounds": [{"type": "direct", "tag": "direct"}, {"type": "block", "tag": "block"}],
  "route": {
    "rules": [...],
    "final": "direct",
    "auto_detect_interface": true,
    "default_domain_resolver": {"server": "local"}
  },
  "experimental": {
    "clash_api": {"external_controller": "127.0.0.1:19090", "secret": "...", "default_mode": "rule"},
    "v2ray_api": {
      "listen": "127.0.0.1:19091",
      "stats": {"enabled": true, "inbounds": [...], "users": [...]}
    }
  }
}
```

### 6.2 校验

1. 纯 Python 语义校验：
   - 端口 1–65535；TCP 线路端口不冲突；Hysteria2 UDP 可同端口。
   - Reality 私钥/公钥/short_id 非空；server_name 合法。
   - Hysteria2/Trojan 必须有 ready 证书且文件存在/未过期。
   - SS2022 server key 合法。
   - 用户 name 唯一；UUID/密码非空。
   - 禁用/到期/超配额用户不在配置中。
   - 证书路径不越界（只允许 data_dir）。
2. `sing-box check -c <temp>`：
   - 30 秒超时；失败保留旧配置，记录 stderr 尾部（脱敏）。
   - 最终权威校验。

### 6.3 应用与回滚

```text
web 修改 DB -> desired_revision++
worker 发现 revision 变化
  -> 读取 DB，生成新配置
  -> 写 runtime/config.next.json (0600)
  -> sing-box check
      失败 -> 删除 next，记录 last_error，告警；旧进程继续运行
      成功 -> 保存上一版 config.json + meta
           -> SIGTERM 旧 sing-box（10s，超时 SIGKILL）
           -> 启动 sing-box run -c config.next.json
           -> 观察 1.5s（两次 0.75s）存活
              失败 -> 恢复上一版 config.json，重启旧配置，记录错误/告警
              成功 -> 原子替换 config.json，更新 RuntimeState
```

- 不使用 SIGHUP。
- worker 单进程 + 文件锁串行化。
- 失败指数退避（2s → 4s → … → 60s），直到 DB 变化或管理员点“重试”。
- 日志不记录用户密码/UUID/私钥。

### 6.4 worker 启动/停止

启动：

1. 获取 `runtime/worker.lock`。
2. `paths.ensure()`；检查 sing-box 二进制/版本。
3. 读取 RuntimeState；终止 cmdline 匹配的孤儿 sing-box。
4. 从 DB 生成配置；`sing-box check`；启动。
5. 写 RuntimeState：running/pid/hash/applied_revision/heartbeat。
6. 主循环。

主循环（1 秒 tick）：

| 周期 | 动作 |
|---|---|
| 1s | 检查 desired_revision；必要时 apply |
| 5s | 查询 V2Ray 统计；更新 rates/online；写 `runtime/usage.json` |
| 5s | 更新 heartbeat |
| 30s | 配额/到期检查；必要时 disable + mark revision |
| 60s | flush 流量到 DB |
| 5min | 检查 sing-box 存活；异常重启/告警 |
| 1h | 清理会话/审计/任务/日志；证书/磁盘检查 |
| 每天 | 自动备份（可选） |

停止：

- SIGTERM → 停止循环 → SIGTERM sing-box（10s，必要时 SIGKILL）→ 写状态 → 释放锁。
- SIGKILL → systemd 重启；启动时清理孤儿。

### 6.5 统计与配额

**统计来源**：sing-box `experimental.v2ray_api` gRPC `127.0.0.1:19091`。

- 每 5 秒 `QueryStats`，正则 `^user>>>[^>]+>>>traffic>>>(uplink|downlink)$`。
- 第一次采样只做基线；之后 delta。
- 计数下降视为重启，开启新 epoch，delta = 当前值。
- `runtime/usage.json` 原子写入，供 web 读。
- 每 60 秒 flush：
  - `used_bytes = F("used_bytes") + total`；
  - `TrafficDaily` 增量；
  - `StatsEpoch` 切换；
  - 提交后清 pending；失败保留。
- 每 30 秒配额：
  - 月周期跨月：used=0、cycle_started_at=now、新 epoch；quota 禁用则恢复。
  - 到期：enabled=False, reason=expired。
  - 超配额（含 pending）：enabled=False, reason=quota_exceeded。
  - 80/90% 告警；状态变化 mark_dirty。
  - 统计不可用 >5min critical alert；配额仍按 DB 执行。
- 配置生成二次过滤。
- 在线 = 最近 60 秒有流量增长；不是 TCP 连接数。
- 速率连续两个静默 tick 归零；统计不可用归零。

### 6.6 DNS 与出口 ACL

- `server_dns_mode`：`auto`（默认）/`doh`/`udp`。
  - auto：探测 DoH；成功用 DoH，失败回退 UDP + 告警。
  - doh：失败则拒绝 apply（fail closed）。
  - udp：不探测。
- `server_dns_doh_url` 默认 `https://1.1.1.1/dns-query`；HTTPS/无凭据；IP 映射证书名。
- `dns.strategy` 默认 `ipv4_only`。
- 出口 ACL：
  - 阻止 RFC1918、CGNAT、link-local、loopback、云 metadata、组播/保留段。
  - 始终阻止 SMTP 25。
  - `block_private_egress` 可关闭私网阻断，但 25 仍阻止。
- `route.auto_detect_interface=true`；`default_domain_resolver` 指向 `local`。

### 6.7 Clash API / 实时连接

- `experimental.clash_api` 监听 `127.0.0.1:19090`，secret 存 `runtime/clash.secret` 0600。
- web 通过 `ClashClient` 读取 `/connections`、`/proxies`、`/version`；关闭单连接/全部。
- 仅回环；secret 不写日志/诊断。
- HTMX 每 5 秒刷新；无 WebSocket。

### 6.8 健康与告警

- worker 每 5 秒 heartbeat；`/readyz` 检查 DB、heartbeat <15s、sing-box running/pid。
- 告警：worker_down、singbox_down、config_apply_failed、stats_unavailable、certificate_expiring、disk_low、quota_80/90/exceeded、backup_failed。
- 去重 fingerprint；Admin 确认；可选 webhook（HMAC-SHA256、3 次重试、禁私网/metadata）。

## 7. 标准订阅

### 7.1 端点

| 路径 | 内容 | Content-Type |
|---|---|---|
| `/sub/{token}` | Base64 URI 列表（默认） | `text/plain; charset=utf-8` |
| `/sub/{token}?target=uri` | 纯 URI 列表 | `text/plain` |
| `/sub/{token}?target=clash` | Mihomo/Clash YAML | `text/yaml` |
| `/sub/{token}?target=singbox` | sing-box 完整配置 | `application/json` |
| `/sub/{token}/v2ray` | 等价默认 | `text/plain` |
| `/sub/{token}/clash` | 等价 clash | `text/yaml` |
| `/sub/{token}/singbox` | 等价 singbox | `application/json` |

别名：`format=`、`flag=` 等价 `target=`；`base64` 等价默认；`sing-box` 等价 `singbox`；`clash-meta`/`clash.meta` 等价 `clash`。未知 target → 400。

### 7.2 响应头

```http
Subscription-Userinfo: upload=<up>; download=<down>; total=<quota>; expire=<unix>
Profile-Update-Interval: 24
Profile-Title: <user>@<server_name>
Content-Disposition: attachment; filename="ostium-<user>.<ext>"; filename*=UTF-8''...
Cache-Control: private, no-store
Pragma: no-cache
Referrer-Policy: no-referrer
X-Content-Type-Options: nosniff
X-Robots-Tag: noindex, nofollow
```

- total=0 表示不限；expire=0 表示不过期。
- 不返回 Set-Cookie；不依赖管理员会话；不做 CORS。

### 7.3 状态码与限速

| 情况 | 状态 |
|---|---|
| token 不存在/格式错误 | 404 |
| 禁用/到期/超配额 | 403 |
| 无可用线路 | 403 |
| 未知 target | 400 |
| 限速 | 429 + Retry-After |
| 正常 | 200 |

- 每 IP 60 次/分钟；每 token 120 次/分钟。
- `X-Forwarded-For` 只信任 Caddy 最后一跳。

### 7.4 端点模型

`subscriptions/endpoints.py`：

- `Endpoint` dataclass：protocol、server、port、uuid/password/ss_password、tls、flow、obfs、name。
- `build_endpoints(user)`：
  - 只取 enabled inbound。
  - Hysteria2/Trojan 必须有 ready 证书。
  - Reality 必须有密钥。
  - SS2022 客户端密码 `server_key:user_key`。
  - 显示名 `<public host> · <protocol>`；不含 token。
  - 顺序 Reality/Hysteria2/Trojan/SS2022。
- `to_uri()`、`to_clash_proxy()`、`to_singbox_outbound()`。

**URI 规范**：

```text
vless://<uuid>@<host>:<port>?encryption=none&security=reality&sni=<sni>&fp=chrome&pbk=<pbk>&sid=<sid>&type=tcp&flow=xtls-rprx-vision#<name>
hysteria2://<password>@<host>:<port>?sni=<sni>&insecure=0[&obfs=salamander&obfs-password=<pwd>]#<name>
trojan://<password>@<host>:<port>?security=tls&sni=<sni>&type=tcp&allowInsecure=0#<name>
ss://<base64url(method:password)>@<host>:<port>#<name>
```

- 参数 quote；IPv6 `[]`；中文 percent-encode。
- SS2022 SIP002 URL-safe base64 无 padding。
- 默认 `insecure=0`；自签证书用 `pinSHA256`/`certificate_sha256`，不默认跳过校验。

**Clash/Mihomo YAML**：

- `mixed-port: 7890`、`allow-lan: false`、`mode: rule`、`log-level: info`、`ipv6: false`。
- DNS：fake-ip、`198.18.0.1/16`、`1.1.1.1/8.8.8.8` bootstrap、DoH nameserver、fallback-filter。
- proxies、`Ostium` select、`Auto` url-test（180s/tolerance 50）。
- rules：local/private 直连、`GEOIP,CN,DIRECT,no-resolve`、`MATCH,Ostium`。
- `yaml.safe_dump(sort_keys=False, allow_unicode=True)`；CI `mihomo -t`。

**sing-box JSON**：

- 完整客户端配置：log/dns/inbounds(mixed 7890)/outbounds(urltest+selector+direct)/route/experimental.cache_file。
- 不启用 TUN。
- `json.dumps(indent=2, ensure_ascii=False)`；CI `sing-box check`。

## 9. 安全模型

### 9.1 管理面

| 控制 | 实现 |
|---|---|
| 密码 | Django Argon2id |
| 会话 | Django session；HttpOnly、SameSite=Lax/Strict、Secure |
| CSRF | Django CSRF middleware |
| TOTP | django-otp；公网管理面强制 |
| 登录锁定 | django-axes（IP+用户名，5 次/15 分钟） |
| 限速 | django-ratelimit |
| Host | ALLOWED_HOSTS + CSRF_TRUSTED_ORIGINS |
| CSP | Django 6.1 SECURE_CSP；`/admin/` 因 Unfold 标准 Alpine 单独放行 `unsafe-eval`，控制台保持严格 CSP |
| HSTS/HTTPS | 生产 settings + Caddy |
| 点击劫持 | X_FRAME_OPTIONS=DENY |
| MIME | SECURE_CONTENT_TYPE_NOSNIFF |
| Referrer | SECURE_REFERRER_POLICY=same-origin；订阅响应单独 no-referrer |
| Admin 默认回环 | Gunicorn 127.0.0.1:8000 |
| 公网管理 | 必须 TOTP+TLS；启动检查 |
| 审计 | django-auditlog + AuditEvent |
| API key | 哈希、scope、过期、撤销、限速 |

### 9.2 订阅面

- token 32 字节随机；SHA-256 哈希 + AES-GCM 加密副本。
- 常量时间比较；未知 token 404。
- 禁用/到期/超配额 403。
- no-store/no-referrer/noindex。
- 日志/审计不记 token；URL 打码。
- 轮换立即失效。
- IP+token 限速；代理头只信任 Caddy。

### 9.3 数据面

- sing-box 固定二进制、SHA256、最小标签。
- 配置只来自 DB 模型；不接受任意 JSON。
- `sing-box check` 后才替换；失败回滚。
- 配置/密钥 0600；目录 0700。
- worker 非 root，仅 CAP_NET_BIND_SERVICE。
- 出口 ACL：私有/metadata/link-local/SMTP 25。
- Clash/V2Ray API 仅回环；secret 0600。

### 9.4 字段加密

- `OSTIUM_SECRET_KEY`：Django 签名；环境变量。
- `OSTIUM_FIELD_KEY`：32 字节 base64；AES-256-GCM。
- AAD 绑定 `app.model:pk:field`；UUID PK。
- 密钥轮换：`ostium rotate-field-key` 重加密；保留旧 key 过渡。
- 备份加密；未加密需显式确认。
- 日志脱敏：UUID/token/password/private key/URI/Authorization。

### 9.5 供应链

- `uv.lock` 锁定；pip-audit/bandit。
- sing-box 固定 tag + SHA256 + SBOM。
- Docker 基础镜像固定 digest；非 root；只读根文件系统。
- GitHub Actions 最小权限；发布环境审批。
- 不静默自动更新。

### 9.6 残余风险

- web/worker 同用户：web 被攻破可影响 worker；服务端无 root/TUN，影响面小于客户端模式。未来可拆 worker 用户。
- worker 重启/升级断隧道 1–3 秒。
- certbot/Caddy 外部依赖。
- SQLite 多进程写锁；高并发用 Postgres。
- 订阅格式兼容性依赖客户端；CI 覆盖 Mihomo/sing-box，v2rayN/Shadowrocket 人工验收。
- 0.1.x 数据不迁移；旧用户需重建。

### 10.3 Docker Compose

### 10.4 安装器

`install.sh`：

1. root/Linux/systemd 检查（`--no-service` 可选）。
2. 安装 `curl`、`ca-certificates`、`certbot`（可选）、`caddy`（可选）。
3. 下载静态 `uv`；`uv python install 3.14`；创建 `/opt/ostium/venv`。
4. 下载 wheel + sing-box + SHA256SUMS；校验。
5. 创建 `ostium` 用户/组/目录/权限。
6. 生成 `/etc/ostium/ostium.env`：
   - `OSTIUM_SECRET_KEY` 随机
   - `OSTIUM_FIELD_KEY` 随机
   - `OSTIUM_DB_URL=sqlite:////var/lib/ostium/ostium.db`
   - `OSTIUM_ALLOWED_HOSTS`
   - `OSTIUM_PUBLIC_BASE_URL`
   - `OSTIUM_SINGBOX_PATH=/opt/ostium/core/sing-box`
7. `ostium migrate`、`collectstatic`、`init`（一次性密码）、`inbound init`。
8. 安装/启用 web/worker/jobs。
9. 健康检查；打印 SSH 隧道和 `http://127.0.0.1:8000/admin/`。
10. `--with-caddy --domain`：写 Caddyfile，启用 Caddy；提示先 TOTP 再公网。

升级：备份 → 停服务 → 新 venv → migrate → 启动 → 健康检查 → 失败回滚。
卸载：停/禁用 → 删 unit → 保留数据；`--purge` 删除数据。

### 10.5 备份 / 恢复

- 内容：DB dump、certs、config、字段密钥、manifest（版本/校验和）。
- 默认加密；未加密需 `--acknowledge-plaintext`。
- 恢复：校验 manifest/checksums/DB 完整性 → migrate → 替换 DB/certs/key → 重启 worker。
- Web 恢复：staging + 重启应用；失败保留错误文件。
- 自动备份：django-q2 每日；保留 7 份；失败告警。

### 10.6 诊断

- DB/迁移/完整性。
- 数据目录权限/磁盘。
- sing-box 二进制/版本/check。
- worker heartbeat/sing-box running/hash。
- 端口 8000/443/80。
- DoH/系统 DNS。
- 证书到期/文件。
- systemd 单元。
- NTP 偏差。
- 诊断包 tar.gz：版本/配置脱敏/日志 tail/端口/证书/DB 统计；0600。

## 14. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| Django Admin 不够精美 | 管理体验下降 | Unfold + 自定义 Tailwind 控制台 + 5 个核心页面精修 |
| Tailwind 与 Unfold 样式冲突 | UI 不一致 | Phase 0 spike；共享 CSS 变量；必要时隔离作用域 |
| SQLite web+worker 写锁 | 偶发 locked | WAL、IMMEDIATE、短事务、busy_timeout；Postgres 可选 |
| worker 重启断隧道 | 短暂中断 | systemd Restart；快速启动；文档；未来可拆 systemd sing-box |
| certbot/Caddy 部署复杂 | 安装失败 | 安装器可选；默认 SSH 隧道；doctor；详细 docs |
| 订阅客户端兼容性 | 导入失败 | 默认 Base64；Mihomo/sing-box 契约；兼容性表；纯 URI |
| 最小 sing-box 标签不支持某协议 | 数据面不可用 | Phase 0 spike；保留必要标签 |
| Django 6.1 非 LTS | 支持窗口短 | 计划 2027 升级 6.2 LTS；锁补丁版本 |
| 合并 web/worker 信任边界 | 攻击面变化 | 服务端无 root/TUN；worker 只执行固定二进制；威胁模型；未来可拆用户 |
| 零迁移导致旧用户流失 | 投诉 | 明确 breaking；旧实例可继续运行；新实例重新建用户；文档 |
| UI 工作量超预期 | 延期 | Admin 先可用，再做精修；页面优先级：Dashboard/Users/Subscriptions/System |
| 供应链/二进制篡改 | 安全 | 固定版本/SHA256/SBOM/attestation |

## 17. 总结

Ostium 0.2.0 是一次**干净的服务端重建**：

- 删掉客户端、SPA、自研 core API、自研 ACME、自研基础设施。
- 用 Django 6.1 的认证/Admin/ORM/迁移/任务/审计做骨架。
- 用 worker 直接监督 sing-box，减少一层自研协议。
- 用 certbot/Caddy 处理证书与管理面 TLS。
- 用四种标准订阅替代私有格式。
- 用 Aurora Server Console 做出现代、精美、可用的管理界面。
- 不迁移、不兼容、不保留 0.1.x 任何文件。

按 Phase 0 → Phase 8 推进，约 5–6 周可到 0.2.0 发布候选。
