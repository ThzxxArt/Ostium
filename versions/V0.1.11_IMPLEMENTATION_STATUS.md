## 6. 复核中发现并修复的问题

1. 源码 checkout 中 `_version.py` 被 hatch-vcs 重写为 `.dev` 时版本会漂移；改为源码优先读取 `VERSION`。
2. DNS 对照把“不同 CDN 公网 IP”误判为污染；改为只对已知劫持网段/私有地址判 fail，其余 warn。
3. fail-open 恢复代理失败时仍清除 pending，导致不再重试；改为保留 pending 并在下一 tick 重试。
4. `system.proxy` 保存配置失败时内存 mode 未回滚；已恢复原 mode/client_paused。
5. Users/Rules/Profiles/Settings 的部分操作忽略 `applied=false`；已统一显示警告。
6. Users 在线标签硬编码 60 秒；改为使用 API 的动态窗口。
7. Windows `-NoStart` 仍被安装脚本健康检查阻塞；已传递 `OSTIUM_NO_START` 并跳过启动/健康检查。
8. Linux 客户端未检查 8787 旧监听、升级后未断言 UI 版本；已补齐。
9. Windows 系统代理 state 丢失时只支持卸载清理，不识别启动恢复；已补 `status`/`recover_if_stale`/`disable_if_owned`。
10. macOS TUN 可用性被 UI 权限误判；改为由特权核心提供 utun。
11. 诊断下载缺少 `no-store`；系统诊断响应统一 no-store，hashed assets 设置 immutable。
12. 显式 `doh` 模式探测失败会清空 last-good selection，后续管理操作可能静默生成 UDP；改为保留上次选择并让 preview fail-closed。
13. TUN 模式没有 mixed 端口，selftest/egress 仍走 `127.0.0.1:mixed_port`；改为 TUN 直连检测，并在核心未运行时拒绝伪造成功。
14. Stats 页面未轮询；已补可见时 10 秒刷新。Subscriptions 轮询会重新隐藏已 reveal 的令牌，已保留 reveal 状态。
15. `/system/provenance` 未把监听 PID 不是当前进程算作不一致；已加入 `listener` mismatch。
16. DoH URL 未拒绝 userinfo；已拒绝带凭据 URL，并在 Settings API 校验。
17. Linux `fuser` 回退把端口号当 PID；已提取冒号后的 PID。
18. macOS fresh install 在权限尚未生效时可能因 UI 健康检查直接失败；改为明确 warning，升级仍 fail。
19. Windows 卸载先强杀 8788 再 Stop-Service 可能导致服务卡住；已调整停止顺序。
